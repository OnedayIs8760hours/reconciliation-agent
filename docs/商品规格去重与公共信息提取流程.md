# 商品规格去重与公共信息提取流程

> 本流程只负责：从 A 表、B 表中获取用于商品关联的规格字段，先由程序去空、去重，再由 AI 分析双方商品命名差异，提取公共商品信息，并生成可用于后续对账的商品映射关系。

---

## 1. 前置条件

前置步骤已经由 AI 判断出：

```text
A 表商品关联字段 = 型号
B 表商品关联字段 = 规格
```

例如华悦案例：

```text
A 表：5月华悦入仓对账单(2)
商品字段：型号
```

```text
B 表：5月华悦-吉客云
商品字段：规格
```

---

## 2. 读取 A、B 商品字段完整数据

Agent 调用 Excel 工具读取整列：

```text
get_column_values(A, "型号")
get_column_values(B, "规格")
```

A 表原始数据示例：

```text
9603公仔桶身150款米色*新
9603公仔桶身90款米色*新
9603公仔桶身120款米色*新
9603公仔桶身150款米色*新
```

B 表原始数据示例：

```text
HYGJ9603-公仔桶身-150款-米色*新
HYGJ9603-公仔桶身-90款-米色*新
HYGJ9603-公仔桶身-120款-米色*新
HYGJ9603-公仔桶身-150款-米色*新
```

---

## 3. 程序先去空、去重

去重属于确定性操作，不需要交给 AI。

程序处理：

```text
去除空值
去除重复值
去除首尾空格
统一全角 / 半角字符
```

A 表去重后：

```json
[
  "9603公仔桶身150款米色*新",
  "9603公仔桶身90款米色*新",
  "9603公仔桶身120款米色*新"
]
```

B 表去重后：

```json
[
  "HYGJ9603-公仔桶身-150款-米色*新",
  "HYGJ9603-公仔桶身-90款-米色*新",
  "HYGJ9603-公仔桶身-120款-米色*新"
]
```

---

## 4. 基础字符串清洗原则

程序只做基础格式清洗。

允许处理：

```text
首尾空格
特殊空格
全角 / 半角差异
换行符
明显无意义的格式字符
```

不要擅自删除：

```text
数字
型号
颜色
“款”
“新”
*
```

因为这些字段可能都是商品身份的重要组成部分。

原则：

```text
格式清洗由程序完成
业务语义判断交给 AI
```

---

## 5. 将去重后的商品列表交给 AI

发送给 AI 的数据：

```json
{
  "a_products": [
    "9603公仔桶身150款米色*新",
    "9603公仔桶身90款米色*新",
    "9603公仔桶身120款米色*新"
  ],

  "b_products": [
    "HYGJ9603-公仔桶身-150款-米色*新",
    "HYGJ9603-公仔桶身-90款-米色*新",
    "HYGJ9603-公仔桶身-120款-米色*新"
  ]
}
```

AI 此时的任务不是去重。

AI 只负责：

```text
分析 A、B 两边商品命名规律
识别双方公共商品信息
识别无业务意义的前缀、分隔符等差异
建立 A 商品与 B 商品之间的对应关系
```

---

## 6. AI 分析命名差异

例如：

```text
A：
9603公仔桶身150款米色*新
```

```text
B：
HYGJ9603-公仔桶身-150款-米色*新
```

AI 可以识别：

```text
B 表额外前缀：HYGJ
B 表额外使用 "-" 作为分隔符
```

双方真正共同的商品信息为：

```text
9603
公仔桶身
150款
米色
*新
```

因此可以得到统一商品表示：

```text
9603公仔桶身150款米色*新
```

---

## 7. 提取标准商品列表

最终可以得到：

```json
[
  "9603公仔桶身150款米色*新",
  "9603公仔桶身90款米色*新",
  "9603公仔桶身120款米色*新"
]
```

这个列表用于表示双方已经确认可以关联的公共商品规格。

---

## 8. 推荐保留原始映射关系

不要只保存标准商品列表。

更推荐同时保存：

```text
A 原始值
↓
标准商品
↓
B 原始值
```

示例：

```json
[
  {
    "standard": "9603公仔桶身150款米色*新",
    "a_value": "9603公仔桶身150款米色*新",
    "b_value": "HYGJ9603-公仔桶身-150款-米色*新"
  },

  {
    "standard": "9603公仔桶身90款米色*新",
    "a_value": "9603公仔桶身90款米色*新",
    "b_value": "HYGJ9603-公仔桶身-90款-米色*新"
  },

  {
    "standard": "9603公仔桶身120款米色*新",
    "a_value": "9603公仔桶身120款米色*新",
    "b_value": "HYGJ9603-公仔桶身-120款-米色*新"
  }
]
```

这样后续正式对账时，可以直接根据 A 表原始商品找到对应的 B 表规格。

---

## 9. AI 推荐输出结构

推荐要求 AI 输出：

```json
{
  "normalization_rules": {
    "b_prefix_to_ignore": [
      "HYGJ"
    ],

    "ignorable_separators": [
      "-"
    ]
  },

  "mappings": [
    {
      "standard": "9603公仔桶身150款米色*新",
      "a_value": "9603公仔桶身150款米色*新",
      "b_value": "HYGJ9603-公仔桶身-150款-米色*新",
      "confidence": 1.0,
      "reason": "型号、商品主体、款式、颜色和状态一致，仅B表增加系统前缀和连接符。"
    }
  ],

  "unmatched_a": [],

  "unmatched_b": [],

  "need_review": []
}
```

---

## 10. 未匹配商品处理

如果 A 表存在：

```text
9603公仔桶身180款蓝色
```

但 B 表中不存在明显对应商品，AI 不应该强行匹配。

应该返回：

```json
{
  "unmatched_a": [
    "9603公仔桶身180款蓝色"
  ]
}
```

后续系统可提示：

```text
存在 A 表商品暂未建立 B 表商品映射关系。
```

---

## 11. 待复核商品处理

如果双方高度相似，但存在关键属性差异，例如：

```text
A：
9603公仔桶身150款米色
```

```text
B：
HYGJ9603-公仔桶身-150款-米黄色
```

AI 不应直接确认完全匹配。

应该返回：

```json
{
  "need_review": [
    {
      "a_value": "9603公仔桶身150款米色",
      "b_value": "HYGJ9603-公仔桶身-150款-米黄色",
      "confidence": 0.78,
      "reason": "型号和款式一致，但颜色描述存在差异。"
    }
  ]
}
```

---

## 12. 最终流程

```text
读取 A 商品列
        ↓
读取 B 商品列
        ↓
程序去空
        ↓
程序去重
        ↓
基础格式清洗
        ↓
得到 A_unique
得到 B_unique
        ↓
发送给 AI
        ↓
AI 分析命名规律
        ↓
提取公共商品信息
        ↓
生成标准商品
        ↓
生成：
A原始值 ↔ 标准值 ↔ B原始值
        ↓
输出商品映射表
```

---

## 13. 核心原则

整个过程遵循：

```text
去重由程序完成
语义关系由 AI 判断
映射结果结构化保存
```

AI 不参与 Excel 行级循环，也不负责数量、金额等确定性计算。

这一阶段最终只需要产出一份：

```text
ProductMapping
```

后续正式对账直接消费这份映射结果即可。
