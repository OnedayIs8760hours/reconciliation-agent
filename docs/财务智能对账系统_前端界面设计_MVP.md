# 财务智能对账系统前端界面设计（MVP）

## 1. 文档目标

本文档用于定义财务智能对账系统第一版（MVP）的前端界面布局与核心交互。

第一版的目标不是做一个聊天式 AI 产品，而是做成一个清晰、稳定、可追踪的“对账任务工作台”。

核心流程：

```text
上传 A 表 + B 表
        ↓
选择对账月份
        ↓
开始对账
        ↓
生成 C 表
        ↓
A/B 数据匹配
        ↓
B 表本月记录反向核查
        ↓
最终验收
        ↓
下载 C 表 / 标记后的 B 表 / 查看核查结果
```

系统界面应围绕这一固定流程设计。

---

## 2. 产品定位

第一版不采用 ChatGPT 式聊天窗口。

推荐产品形态：

```text
文件处理工具
+
任务执行流水线
+
财务核查报告
```

用户进入系统后，只需要完成三件事：

1. 上传 A 表。
2. 上传 B 表。
3. 选择对账月份并点击“开始智能对账”。

其余工作由后端对账流程自动完成。

```text

```

左侧：

```text

```



```text

```

## 5.1 A 表上传

标题：

```text
A表 / 业务对账单
```

未上传时：

```text
┌────────────────────────┐
│                        │
│   拖拽 Excel 到这里     │
│                        │
│      或点击上传         │
│                        │
└────────────────────────┘
```

上传完成后，上传区域自动缩小为文件卡片：

```text
┌────────────────────────────┐
│ 📊 2026年7月玖鸣对账单.xlsx │
│                            │
│ 1.8 MB                     │
│                            │
│ ✓ 已上传             更换   │
└────────────────────────────┘
```

这样可以避免上传后仍占据过多页面空间。

# 6. B 表上传

标题：

```text
B表 / 系统出入库明细
```

上传成功后建议增加文件识别提示：

```text
┌────────────────────────────────────┐
│ 📊 台州市川跃家居用品有限公司.xlsx │
│                                    │
│ ✓ 已上传                           │
│ ✓ 已识别为系统出入库表             │
│                             更换    │
└────────────────────────────────────┘
```

系统可以根据文件名、字段结构等方式辅助识别 B 表。

如果用户疑似上传错误：

```text
⚠ 当前文件可能不是系统出入库表
```

并阻止开始对账，或者要求用户确认。

---

# 7. 对账月份

文件上传区域下方增加：

```text
对账月份

[ 2026年07月 ▼ ]
```

第一版建议由用户明确选择月份。

不要完全依赖 Agent 自动推断。

原因：

B 表反向核查只针对当前对账月份的系统出入库记录。

例如：

```text
当前对账月份：2026-07
```

则反向核查：

```text
系统出入库时间属于 2026-07
```

的数据。

# 8. 开始对账按钮

左侧最下方放置唯一主操作按钮：

```text
[ 开始智能对账 ]
```

按钮状态：

### 未满足条件

```text
开始智能对账
```

禁用。

条件：

```text
A表未上传
或
B表未上传
或
月份未选择
```

---

### 可执行

```text
开始智能对账
```

可点击。

---

### 执行中

```text
正在对账...
```

按钮禁用，避免重复提交任务。

# 10. 对账执行进度

顶部显示当前对账任务，例如：

```text
玖鸣 · 2026年7月对账
```

流程建议固定为：

```text
✓ 1. 文件检查
✓ 2. 生成 C 表底稿
● 3. A/B 数据匹配
○ 4. B 表反向核查
○ 5. 最终验收
```

状态定义：

```text
✓ 已完成
● 执行中
○ 未开始
× 执行失败
```

---

## 10.1 当前节点详细信息

正在执行时，可显示：

```text
● 正在匹配 B 表
```

并给出业务可理解的信息：

```text
已处理 C 表业务记录：328 / 541
已匹配 B 表记录：402
需要人工复核：17
```

如果有明确的执行比例，也可以显示进度条：

```text
███████████████░░░ 72%
```

---

## 10.2 不展示模型内部推理

前端不建议显示：

```text
Thinking...
模型正在思考...
正在分析规则...
正在进行推理...
```

用户更关心：

```text
任务执行到哪里了
处理了多少记录
有没有异常
最终是否通过核查
```

# 12. B 表本月覆盖情况

核心指标卡下方显示 B 表覆盖统计：

```text
B表本月覆盖情况

本月有效记录        831

已进入 C 表         790
C表缺失已标记        41
人工排除              0
──────────────────────
未解释记录            0
```

覆盖关系必须满足：

```text
B表本月系统记录数
=
C表已承接记录数
+
B表已标注缺失记录数
+
人工排除记录数
```

如果不满足：

```text
未解释记录 > 0
```

则任务不能显示为“核查通过”。

# 20. 推荐状态设计

前端任务状态建议统一：

```ts
type TaskStatus =
  | 'UPLOADED'
  | 'PROCESSING'
  | 'GENERATING'
  | 'MATCHING'
  | 'VERIFYING'
  | 'SUCCESS'
  | 'FAILED'
```

对应界面：

| 状态 | 前端显示 |
|---|---|
| UPLOADED | 文件已上传 |
| PROCESSING | 正在检查文件 |
| GENERATING | 正在生成 C 表 |
| MATCHING | 正在匹配 B 表 |
| VERIFYING | 正在进行反向核查 |
| SUCCESS | 核查通过 |
| FAILED | 核查未通过 |

# 23. MVP 核心原则

第一版前端应始终围绕以下目标：

> 用户上传两个 Excel，选择月份，点击一次按钮，就能完成 C 表生成、B 表匹配、反向核查和最终验收。

界面要让用户清楚知道：

```text
我上传了什么
现在执行到哪一步
有没有异常
核查是否真正通过
最终应该下载什么
```

而不是强调：

```text
AI 在想什么
Agent 调用了什么模型
内部 Prompt 是什么
```

对于财务对账场景，稳定、可追溯、可复核比“聊天感”和“AI 感”更重要。
