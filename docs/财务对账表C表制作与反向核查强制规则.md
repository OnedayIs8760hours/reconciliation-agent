# 财务对账表C表制作与反向核查强制规则

本规则用于补充并强化 [[财务对账表制表逻辑通用指南]]。

原指南适合说明制表逻辑，但单靠文字规则不稳定。后续制作 C 表时，必须把本规则转化为生成脚本和核查脚本。生成完成但未通过核查的 C 表，不视为完成。

> [!warning] 核心原则
> C 表不能只证明 A 表金额没有变，还必须证明 B 表本月系统记录已经被承接、标注或说明原因。

## 1. 文件定义

### 1.1 A 表

A 表是客户、供应商或业务侧提供的对账底稿。

A 表决定 C 表的原始业务口径，包括：

- 日期
- 票据单号
- 产品名称
- 单位
- 数量
- 单价
- 金额
- 备注

### 1.2 B 表

B 表是系统导出的出入库明细。

文件名以 `台州` 开头的 Excel 一律视为 B 表。

B 表关键字段：

| B 表列 | 字段 | 用途 |
| --- | --- | --- |
| E | 仓库 | 追溯仓库来源 |
| F | 系统出入库时间 | 判断本月范围和日期复核 |
| G | 单据编号 | 追溯系统单据 |
| H | 货品编号 | 辅助匹配 |
| I | 货品名称 | 辅助匹配 |
| J | 规格 | 与 A/C 表产品名称、规格匹配 |
| K | 入库数量 | 正数业务匹配 |
| L | 入库成本单价 | 入库单价 |
| M | 入库成本金额 | 入库金额 |
| N | 出库数量 | 负数业务匹配 |
| O | 出库成本单价 | 出库单价 |
| P | 出库成本金额 | 出库金额 |

### 1.3 C 表

C 表以 A 表为底稿生成，并追加 B 表匹配字段。

C 表必须同时满足：

1. A 表原始业务数量、金额口径不被破坏。
2. B 表本月系统记录可以在 C 表中追溯，或在 B 表中被标注为 C 表缺失。

## 2. 制作总流程

每个任务必须分成三步执行：

```text
第一步：A 表生成 C 表底稿
第二步：C 表按 A 表明细匹配 B 表
第三步：B 表按本月系统时间反向核查 C 表
```

第三步是强制步骤，不能省略。

## 3. A 表生成 C 表底稿规则

### 3.1 完整复制

C 表必须从 A 表完整复制生成。

不得只抽取部分字段重新拼表。

### 3.2 合并单元格处理

取消合并单元格后，日期列必须向下填充。

如果取消合并后不填充日期，后续匹配 B 表时会丢失日期依据。

### 3.3 日期显示格式

C 表日期建议统一显示为：

```text
7月1日
7月2日
```

但内部核查脚本必须能识别：

```text
2026.7.1
2026-07-01
7月1日
Excel 日期序列值
```

### 3.4 底色清理

C 表生成后，应清除 A 表原有底色。

后续匹配状态、缺失标注、人工复核标注使用新的颜色体系。

## 4. C 表正负数匹配 B 表规则

### 4.1 正数匹配入库

C 表原始业务数量为正数时，匹配 B 表入库字段：

```text
C 表数量 > 0
匹配 B 表 K-M：入库数量、入库成本单价、入库成本金额
```

### 4.2 负数匹配出库

C 表原始业务数量为负数时，必须匹配 B 表出库字段：

```text
C 表数量 < 0
匹配 B 表 N-P：出库数量、出库成本单价、出库成本金额
```

注意：

- B 表出库数量通常为正数。
- C 表负数与 B 表出库数量比较时，应使用绝对值。
- C 表金额为负数，B 表出库金额通常为正数，比较时也应使用绝对值。
- C 表中必须增加 `匹配方向` 字段，明确写入 `入库` 或 `出库`。

### 4.3 零数量或零金额

零数量、零金额、补发件、配件补数不能自动忽略。

处理规则：

1. 如果 B 表存在系统记录，即使金额为 0，也要承接到 C 表或标注为缺失。
2. 如果 A 表金额为 0，但 B 表有补发仓记录，仍应保留 B 表追溯字段。
3. 无法判断时，标记为 `零金额需复核` 或 `补发件需复核`。

## 5. 匹配依据规则

### 5.1 优先匹配项

优先使用以下字段组合：

```text
日期 + 货品编号 + 规格 + 数量 + 单价
```

如果货品编号缺失，可使用：

```text
日期 + 规格/产品名称 + 数量 + 单价
```

### 5.2 日期允许复核

业务日期和系统日期可能不完全一致。

如果数量、单价、货品编号或规格可以支撑对应关系，但日期不一致，应标记为：

```text
已匹配/日期需复核
已匹配/日期规格需复核
```

不要因为日期不完全一致就直接丢弃 B 表记录。

### 5.3 规格允许复核

A 表和 B 表规格经常存在简称、别名、颜色写法、型号前缀差异。

数量和单价能对上时，可以标记为：

```text
已匹配/规格需复核
```

匹配依据中必须说明：

```text
数量一致，规格文字不完全一致，需人工复核
```

## 6. 多行匹配规则

### 6.1 不得只写合计

如果一条 A/C 表记录对应 B 表多条记录，C 表必须展开为多行。

错误做法：

```text
只把 B 表多行数量合计写在 C 表一行
```

正确做法：

```text
B 表匹配几行，C 表就展开几行
每一行保留一条 B 表原始记录
```

### 6.2 不得只查连续 2 行或 3 行

连续 2 行或连续 3 行只是最低匹配能力，不是完整规则。

实际业务中，B 表同一 A 表业务可能被拆到多行，且这些行不一定连续，中间可能夹着其他货品。

因此脚本必须支持：

1. 连续多行数量合计匹配。
2. 同单据编号下非连续多行数量合计匹配。
3. 同货品编号、同规格、同系统日期下非连续多行数量合计匹配。
4. 同货品编号、规格相似、日期需复核的多行数量合计匹配。

如果只支持连续 2/3 行，会导致 B 表记录在 C 表右侧追溯字段中丢失。

### 6.3 插入行留空规则

多行匹配时，插入行不是 A 表新增业务。

插入行中，A 表原始业务列应保持空白。

只填写：

- 匹配状态
- 匹配依据
- B 表行号
- 匹配方向
- B 表追溯字段
- 入库或出库数量、单价、金额

## 7. B 表追溯字段必须完整保留

C 表承接 B 表记录时，不能只保留数量、单价、金额。

必须完整保留：

```text
仓库
系统出入库时间
单据编号
货品编号
货品名称
规格
入库数量 / 出库数量
入库成本单价 / 出库成本单价
入库成本金额 / 出库成本金额
```

缺少这些字段，会导致后续人工无法从 C 表反查 B 表系统记录。

## 8. B 表本月记录反向核查规则

### 8.1 为什么必须反向核查

只从 A 表出发生成 C 表，会出现一个问题：

```text
A 表金额能对上
但 B 表本月系统记录没有全部进入 C 表
```

这说明 C 表没有破坏 A 表金额，但丢失了 B 表追溯数据。

因此必须反向核查 B 表。

### 8.2 本月范围

反向核查只看当前对账月份的 B 表系统时间。

例如制作 7 月 C 表时：

```text
只看 B 表 系统出入库时间 = 2026-07
不看 2026-08
```

除非业务明确要求跨月追溯，否则 8 月系统时间不纳入 7 月 C 表缺失统计。

### 8.3 反向核查字段

用 B 表以下字段组成追溯键：

```text
仓库
系统出入库时间
单据编号
货品编号
货品名称
规格
入库数量 / 出库数量
入库成本单价 / 出库成本单价
入库成本金额 / 出库成本金额
```

入库核查：

```text
B 表 E-J + K-M
必须能在 C 表 B 追溯字段中找到
```

出库核查：

```text
B 表 E-J + N-P
必须能在 C 表 B 追溯字段中找到
```

出库比较时，C 表负数金额和 B 表正数出库金额按绝对值比较。

### 8.4 反向核查结果

每条 B 表本月记录必须落入以下三类之一：

| 类型 | 说明 |
| --- | --- |
| 已承接 | B 表记录已经写入 C 表追溯字段 |
| 已标注缺失 | B 表记录未写入 C 表，但已在 B 表中标注 |
| 人工排除 | 有明确业务原因不纳入 C 表 |

不能出现：

```text
B 表本月记录既没进 C 表，也没在 B 表标注
```

## 9. B 表缺失标注规则

当 B 表本月系统记录没有在 C 表中找到时，必须在 B 表右侧追加标注列。

建议字段：

| 标注列 | 内容 |
| --- | --- |
| C表缺失标注 | C表缺失 |
| 缺失类型 | 入库缺失 / 出库缺失 / 零金额缺失 / 空数量 |
| 人工表行号 | 如果有人工调整表，记录人工表行号 |
| 缺失匹配依据 | 人工表有，C表无；仅统计本月系统时间 |
| 标注说明 | 说明为什么标注 |

标注行建议使用浅黄色底色。

如果没有人工表，也应在 B 表中标注：

```text
B表本月记录未在C表中找到
```

## 10. 合计公式核查规则

### 10.1 插行后必须重写合计公式

C 表插入 B 表拆分行后，原 A 表合计行会下移。

合计公式必须按新行号重写。

示例：

```text
A 表原公式：G545 = SUM(G4:G544)
C 表插入行后合计行变为 G571
错误：G571 = SUM(G4:G544)
正确：G571 = SUM(G4:G570)
```

### 10.2 明细金额公式处理

如果 A 表明细金额列存在公式，生成 C 表时优先写入公式计算后的数值。

原因：

```text
插行可能导致相对引用错位
```

### 10.3 金额列显示

金额列宽必须足够。

不能出现：

```text
########
```

## 11. C 表交付前强制验收

交付前必须运行核查脚本。

### 11.1 A 表口径核查

必须满足：

```text
C 表原始业务数量合计 = A 表原始业务数量合计
C 表原始业务金额合计 = A 表原始业务金额合计
差额 = 0
```

这里的原始业务列不包括 B 表追加的追溯字段。

### 11.2 B 表本月覆盖核查

必须满足：

```text
B 表本月系统时间记录数
= C 表已承接记录数 + B 表已标注缺失记录数 + 人工排除记录数
```

如果不满足，不能交付。

### 11.3 公式错误核查

必须扫描：

```text
#REF!
#DIV/0!
#VALUE!
#NAME?
#N/A
```

错误数量必须为 0。

### 11.4 视图核查

保存 C 表前必须复位视图：

```text
topLeftCell = A1
activeCell = A1
冻结窗格 = 表头下一行
```

避免打开文件时直接跳到表格底部。

## 12. 芳华案例复盘

### 12.1 问题现象

芳华 C 表与人工调整表对比时，A 表金额口径能对上，但 C 表右侧 B 表追溯字段缺少一批记录。

按系统时间只看 7 月后，在 B 表中标注出：

| 类型 | 数量 |
| --- | ---: |
| 入库缺失 | 19 |
| 出库缺失 | 63 |
| 合计 | 82 |

### 12.2 直接原因

这些记录不是 A 表金额丢失，而是 B 表 7 月系统记录没有被 C 表承接。

主要集中在：

1. 负数退货对应的 B 表出库记录。
2. 多行拆分但不一定连续的 B 表记录。
3. 零金额补发件记录。
4. 日期需要复核但仍属于 7 月系统时间的记录。

### 12.3 规则结论

以后不能只问：

```text
A 表和 C 表金额是否一致？
```

还必须问：

```text
B 表本月系统记录是否全部进入 C 表或被标注？
```

## 13. 后续脚本要求

每个公司任务可以有独立生成脚本，但必须包含共同验收逻辑。

建议每个任务至少包含：

```text
generate_xxx_c_table.py
verify_xxx_c_table.py
mark_xxx_b_missing_current_month.py
```

其中 `verify` 和 `mark` 不能只作为人工可选步骤，应作为交付前必跑步骤。

## 14. 最终完成标准

一个 C 表任务只有同时满足以下条件，才算完成：

1. C 表从 A 表完整生成。
2. 正数匹配 B 表入库 K-M。
3. 负数匹配 B 表出库 N-P。
4. 多行匹配逐行展开，不只写合计。
5. 非连续多行也纳入候选匹配。
6. B 表追溯字段完整保留。
7. 零金额、补发件不自动忽略。
8. A/C 原始业务数量、金额一致。
9. C 表合计公式覆盖插行后的全部明细。
10. 明细金额公式无错位风险。
11. B 表本月系统记录已承接、已标注或已人工排除。
12. 公式错误数量为 0。
13. 金额列不显示 `########`。
14. 打开文件时视图停在顶部。

> [!tip] 执行口令
> 以后不要只说“按 MD 做 C 表”。应说：“按 C 表强制规则生成，并运行 A 表口径核查与 B 表本月反向核查；核查不通过先修复脚本和表格。”
