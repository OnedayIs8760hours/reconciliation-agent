# 前端设计规范

## 适用范围

本规范用于 SDS Design 前端页面、工具界面和后续新增业务页面。当前登录界面原型采用的风格作为第一版视觉基准：大量留白、克制色彩、系统字体、轻材质和明确的信息层级。

登录界面当前仍是原型，不代表已完成认证流程。认证状态、权限、会话和后端 API 接入应在后续独立实现。

## 设计方向

- 页面应给人安静、清晰、专业的工作台感受，不做营销页式堆叠。
- 首屏优先展示当前任务入口，不放无关装饰内容。
- 使用大面积留白建立高级感，减少卡片、边框和背景图形的数量。
- 颜色保持低饱和、浅背景、深文字，只用少量系统色做状态和品牌点缀。
- 组件形态应稳定、可维护，避免一次性视觉技巧影响后续扩展。

## 视觉品质与创意标准

- 设计标准对标 Awwwards、FWA、CSS Design Awards 每日最佳网站的精品水准。
- 浏览器可以被视作交互式艺术画布，允许跳出传统后台布局框架，探索先锋视觉风格、实验性排版和高冲击力文字版式。
- 沉浸式页面应融合代码、图形、动效和高级渲染逻辑，形成完整统一的数字体验，而不是拼贴式装饰。
- 高创意自由度不能牺牲业务目标、可读性、可访问性和后续维护性。
- 工具型工作台页面仍以效率和清晰为先；登录、展示、欢迎、作品集、品牌页等更适合承载强视觉表达。
- 复杂动效应具备物理一致性、流畅响应和可中断反馈，并提供减少动效模式。

## 色彩

基础页面背景使用接近白色的浅灰、浅绿灰、浅暖灰组合，例如：

```css
background:
  radial-gradient(circle at 18% 18%, rgb(255 255 255 / 92%) 0 16rem, transparent 31rem),
  linear-gradient(135deg, #f8fafc 0%, #f3f7f4 46%, #fbf4f0 100%);
```

推荐颜色：

- 主文字：`#0f172a`、`#111827`
- 正文文字：`#56616d`
- 辅助文字：`#69737f`
- 主操作按钮：`#111827`
- 蓝色强调：`#007aff`
- 绿色状态点：`#34c759`
- 红色提示点：`#ff5f57`

避免：

- 大面积单一蓝紫渐变。
- 大面积高饱和色块。
- 多个装饰光斑、圆球、复杂 SVG 背景。
- 仅依赖颜色表达状态，状态变化要配合文字或结构。

## 留白与布局

- 登录、欢迎、空状态等入口页应使用宽松布局，内容最大宽度控制在 `1180px` 左右。
- 桌面端可使用左右两栏：左侧品牌与说明，右侧表单或主要操作。
- 移动端必须切换为单列，优先保证主要操作在较少滚动后可见。
- 区块之间使用清晰间距，而不是依赖分割线。
- 不要在页面 section 外包一层大卡片；卡片只用于表单、弹窗、重复列表项或明确需要边界的工具面板。

参考结构：

```text
page
  hero/layout container
    copy area
    action panel
```

## 字体与排版

优先使用系统字体：

```css
font-family: -apple-system, BlinkMacSystemFont, "SF Pro Display", "Segoe UI", "Microsoft YaHei", sans-serif;
```

规则：

- 标题用较大字号和较重字重建立层级，但不要让标题挤压操作区域。
- 不使用随视口连续缩放的字体大小；通过断点设置明确字号。
- 字距统一保持 `letter-spacing: 0`。
- 正文行高保持舒适，建议 `1.5` 到 `1.65`。
- 中文页面后续应优先使用中文业务文案，英文原型文案仅用于当前视觉验证。

## 材质与深度

轻材质可用于登录表单、浮动工具条、顶部栏等功能层：

```css
background: rgb(255 255 255 / 64%);
backdrop-filter: blur(28px) saturate(180%);
box-shadow:
  0 1px 0 rgb(255 255 255 / 88%) inset,
  0 28px 80px rgb(15 23 42 / 12%);
```

规则：

- 大型功能面板可以使用轻透明材质，但不要在透明材质上继续嵌套透明卡片。
- 阴影应柔和，用于表达层级，不用于制造强烈装饰效果。
- 面板圆角默认不超过 `8px`，除非现有设计系统另有要求。
- 需要支持 `prefers-reduced-transparency`，透明材质在该模式下应退化为纯白背景。

## 组件规则

图标：

- 统一使用 Lucide 图标。
- 界面全程禁止使用表情符号作为图标、状态或装饰。
- 有明确 Lucide 图标可表达的操作，不要手写临时 SVG。
- 不熟悉的图标按钮必须提供可访问名称，例如 `aria-label` 或可见文本。

表单：

- 输入框高度建议 `50px` 左右。
- 输入框 focus 使用蓝色描边和低透明度外发光。
- 错误、提示、状态信息放在表单内部的固定区域，避免布局跳动。
- 原型状态必须明确标注，不让用户误以为已接入真实认证。

按钮：

- 主按钮使用深色实底，高对比文字。
- 次要文本按钮使用蓝色文字，不加边框。
- 点击反馈要即时，保持轻微缩放或背景变化。
- 禁用状态要有明显透明度变化，并保留可读性。

标签/状态点：

- 胶囊标签可用于短信息总结。
- 标签内可以使用小圆点表示状态，但文字仍必须完整表达含义。
- 标签用于辅助扫描，不应成为主要导航。

## 动效与可访问性

- 交互反馈应立即发生，例如按钮按下、输入框聚焦。
- 常规页面过渡保持克制，不使用弹跳或大幅位移。
- 可被用户直接操作的元素才考虑更细腻的弹性动效。
- 必须支持 `prefers-reduced-motion`，减少动效时保留颜色和透明度反馈。
- 必须支持键盘可聚焦状态，输入框、按钮和链接都要可达。

## 文件组织

新增页面应按以下方式组织：

```text
frontend/src/pages/
  LoginPrototype.jsx

frontend/src/styles/
  login.css
```

规则：

- 页面级组件放在 `frontend/src/pages/`。
- 页面专属样式放在 `frontend/src/styles/`。
- 通用组件再放入 `frontend/src/components/`，不要过早抽象。
- 不把新页面的大段 JSX 和样式塞进 `App.jsx`。
- `App.jsx` 只保留入口选择和应用壳逻辑。

## 登录原型后续接入要求

当前登录页只做视觉和前端交互原型。后续接认证时应：

- 替换 `LoginPrototype` 中的提交逻辑为真实 API 调用。
- 增加加载、失败、成功、权限不足状态。
- 将 `App.jsx` 中的 `?screen=login` 原型入口替换为正式认证状态判断。
- 认证状态建议独立封装，不和编辑器设计状态混在同一个 store。
- 登录成功后再进入现有编辑器，避免未认证用户直接访问业务界面。

## 检查清单

新增或修改前端页面前检查：

1. 页面是否保持清晰主任务，没有营销化堆叠。
2. 是否使用系统字体、低饱和背景、深色主文字。
3. 首屏是否有足够留白，但移动端主要操作不能过深。
4. 是否避免卡片套卡片。
5. 是否支持减少动效和减少透明度。
6. 页面组件、样式和业务逻辑是否按目录拆分。
7. 图标是否统一使用 Lucide，且没有使用表情符号。
8. 高创意页面是否仍保持可读、可访问、可维护。
9. 是否运行 `npm run build` 验证生产构建。
